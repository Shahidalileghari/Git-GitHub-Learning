# 10 — Pull requests, reviews, and issues

A pull request (PR) proposes integrating changes from one branch into another. It creates a review conversation around a diff.

A good PR includes:
- Problem and context
- Summary of changes
- How it was tested
- Screenshots or logs where useful
- Risks and follow-up work

Review checklist:
- Does the change solve the stated problem?
- Is it understandable and maintainable?
- Are edge cases and security implications considered?
- Are tests appropriate?
- Is documentation updated?

Issues track bugs, tasks, and proposals. Discussions support open-ended community conversations.

Exercise: open a PR from a feature branch, request review, leave a constructive review comment, and update the PR.
